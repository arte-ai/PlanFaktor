# Политика безопасности

Репозиторий Planfaktor публичный: каждый коммит, план и review-артефакт —
акт публикации. Эта политика фиксирует канал отчётов об уязвимостях,
правила обращения с секретами и приватными данными и порядок обзора
публичного артефакта перед публикацией. Машинный барьер — чек C14
corpus-линта (`scripts/check_corpus.sh`); его классы закрывают named-классы
(приватные пути, токены хостинга, маркеры приватных ключей, заголовки
авторизации, JWT-подобные значения), но не заменяют человека (ниже).

## Как сообщить об уязвимости

- Канал отчёта — GitHub private vulnerability reporting репозитория
  `arte-ai/PlanFaktor` (вкладка Security → Report a vulnerability).
  Включение самого механизма в настройках репозитория — действие
  владельца на площадке; этот файл фиксирует канал как канонический.
- Не публикуйте в публичных issues эксплойт-детали, секреты и рабочий
  путь атаки: issue виден всем сразу и до реакции мейнтейнеров.
- Состав полезного репорта:
  - затронутые файлы и версия (коммит или Plan ID);
  - ожидаемое воздействие (что может сделать злоумышленник);
  - безопасные шаги воспроизведения — без рабочего эксплойта и без
    живых значений;
  - минимальная митигация, если она вам известна.

## Секреты и приватные данные

- Не коммитьте секреты, токены, cookies, приватные хостнеймы, приватные
  пути (домашние каталоги) и приватные идентификаторы провайдерных
  сессий. Утечка в публичную историю необратима без переписывания
  истории — не рассчитывайте на «потом удалим».
- Канонический плейсхолдер редакции приватных значений в текстах —
  `<REDACTED>`: маскируйте значение до коммита, не после.
- Разграничение идентификаторов:
  - публичные операционные идентификаторы конвейера — Plan ID, dispatch
    и CENSOR id — легальная публичная evidence, редактировать их не нужно;
  - приватные идентификаторы — provider user/session/SID/thread id,
    креды — редактируются до публикации (плейсхолдером `<REDACTED>`).
- История не переписывается: замороженные коммиты и append-only логи
  планов (`## Evidence`, `## Q&A log`) остаются как есть — защита
  действует вперёд, не ретроспективно. Ретроспективный аудит истории —
  отдельная задача владельца (см. `docs/followups/backlog.md`,
  id=history-secret-audit), не молчаливая правка истории.
- Машинная страховка named-классов — чек C14 corpus-линта
  (`scripts/check_corpus.sh`, прогон из корня репо); полный класс
  приватных идентификаторов (имена, сессии) машинными паттернами не
  покрывается — см. следующий раздел.

## Обзор публичного артефакта перед публикацией

Перед ревью и публикацией каждого нового артефакта (план, review,
плейбук, доки, скрипт) выполните скан на:

- приватные пути — домашние каталоги и другие локи, идентифицирующие
  машину или пользователя;
- ссылки на приватные первоисточники — репозитории, тикеты, документы,
  недоступные публично;
- секрет-подобные значения — токены, ключи, заголовки авторизации,
  JWT-подобные строки.

Автоскан (чек C14) помогает, но не заменяет направленный ручной просмотр
финального артефакта: человек читает контекст, автоматика — только
паттерны.
Описание классов детекции ведётся формулировками без триггерных
литералов и payload-образных примеров — чтобы сам этот файл и
CONTRIBUTING.md не расширяли allowlist чека C14.
