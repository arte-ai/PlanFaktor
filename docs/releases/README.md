# Релизный узел конвейера — конвенция

Каталог `docs/releases/` — носитель релизного узла Planfaktor: замыкает
трассу «требование → план → изменение → верификация → релиз» последним
звеном. Продукт конвейера — сам корпус («целиком в ZCode, без рантайма»,
AGENTS.md), поэтому выпуск — это аннотированный тег, релиз-нота и
переводы статуса требований, а не бинарный артефакт. Релиз — событие
вне статусной машины планов (§2 AGENTS.md): планы и их Owner-гейты
не меняются, отдельного гейта на выпуск в шапке плана нет.

## Определение релиза

Релиз = три сущности вместе:

1. аннотированный git-тег `vX.Y.Z` (semver), указывающий на closeout-хвост
   последнего Done-плана (после `chore(<PlanID>): closeout tail`) либо на
   коммит, явно указанный Owner;
2. релиз-нота `docs/releases/vX.Y.Z.md` — по одному файлу на выпуск
   (один выпуск = один артефакт; единый CHANGELOG.md отклонён — он ломает
   пер-выпускную верифицируемость), создаётся из шаблона
   `docs/releases/_template.md` (доктрина шаблонов, §9 AGENTS.md);
3. переводы `verified → released` в реестре требований
   (docs/requirements/registry.md) с записями журнала.

## Сборка корпуса без рантайма

«Сборка» выпуска — верифицированный снапшот на тегаемом коммите: свежие
прогоны `sh scripts/check_corpus.sh` → `corpus: clean` (exit 0),
`sh scripts/check_corpus.sh --selftest` → selftest caught (exit 0) и
C14 safety-scan (встроенный чек по рабочему дереву); gitleaks по
истории — кандидат history-secret-audit (строка backlog
id=history-secret-audit, `docs/followups/backlog.md`). Это тот же fresh-green
инвариант, что у merge (§8 AGENTS.md): текущий failure не глушится
историческим green — прогон всегда свежий, на тегаемом коммите.
Бинарных артефактов нет; публикация GitHub Releases опциональна при
наличии remote и инвариантом не является (корпус предъявим git-архивом).

## Версионирование

Старт — `v0.1.0`; эпоха 0.x — стабилизация конституции (честный сигнал
зрелости клиенту); переход на `v1.0.0` — явное решение Owner. Инкременты:

- MAJOR — несовместимые изменения контрактов (AGENTS.md, docs/roles/*,
  шаблоны, .zcode/commands/*, scripts/check_corpus.sh);
- MINOR — новые возможности (большинство merge-планов);
- PATCH — точечные фиксы без нового плана.

Версия любого конкретного выпуска — решение Owner; конвенция задаёт
семантику инкрементов, а не автоматический выбор номера.

## Полномочия и процесс

Релиз режет Manager по явному указанию Owner: версия и момент — решение
Owner, тег — git-объект, а единственный писатель git-объектов — Manager
(§8 AGENTS.md). Порядок: указание Owner (версия; при необходимости —
базовый коммит и/или явный список требований) → при MINOR-инкременте —
пересчёт тиров расхода токенов по правилу `docs/reference/budgets.md`
(обновляются числа budgets.md и синхронные им константы границ шагов 6–7
`.zcode/commands/planfaktor-status.md`; коммит чисел — до тега, без
отдельного плана: числа, не контракты) → свежий green-прогон
линта/selftest/C14 на тегаемом коммите → релиз-нота из шаблона →
аннотированный тег → переводы `verified → released` в реестре.
Молчание Owner ничего не режет (owner-silence, §6 AGENTS.md).

## Переводы verified → released

Переводятся требования, реализация которых вошла в выпуск: по умолчанию
все rows в `verified` на момент выпуска, либо явный список Owner.
Переводит Manager; запись журнала реестра — `<ID>: verified → released — <тег>`
(форма и ветка статуса — docs/requirements/README.md, «Отслеживание»).

## Состав релиз-ноты

Нота `docs/releases/vX.Y.Z.md` (из `docs/releases/_template.md`) несёт
пять блоков: шапка выпуска (версия, дата, тег, базовый коммит); вошедшие
планы с прошлого тега (PlanID, тип, тема); требования → released (IDs
и записи журнала); verification-evidence (факты линта/selftest/C14 на
тегаемом коммите); известные ограничения (открытые backlog-хвосты) —
честные границы предъявления клиенту.

## Границы конвенции

5.12 (безопасная система сборки) и 5.13 (безопасность сборочной среды) —
чужие инструментальные процессы, «вне скоупа конвейера» в комплаенс-
маппинге (docs/compliance/gost-r-56939-2024.md). Машинная проверка
формата нот и соответствия тег↔файл — кандидат v2 (сейчас линт C12
валидирует enum статуса `released`, не ноты). Резка первого выпуска
`v0.1.0` — операционное решение Owner после merge плана, закрепившего
эту конвенцию.
