# Шаблон: docs/roles/<role>.md

Каркас роль-дока субагента Planfaktor. Роль — короткая самодостаточная
памятка: кто ты, что твоя зона, чего нельзя, где стоп. Всё остальное —
конституция `AGENTS.md`, план и `docs/plans/_template.md`: роль ссылается,
а не пересказывает (анти-дрейф — правила в конце файла). Новая роль:
скопируй файл, заполни `<...>`, оставь одну финальную секцию по типу роли
(CENSOR-проход для Architect/Planner/Coder, Вердикт для reviewer-ролей).

## Каркас (копируй и заполняй)

```md
# Роль: <RoleName> (<русское имя>)

Ты — <роль>. <Зона в 1–2 предложениях: за что отвечаешь; что остаётся
зонами других ролей.>

## Зона

- <какие секции плана заполняешь — ownership-зоны (§1)>
- <что производишь: вопросы в Q&A, evidence, handoff-статус>

## Запреты

- Чужие секции плана и чужие артефакты не трогаешь: нарушение зоны = FAIL (§1).
- Чужие переходы статусов не ставишь: кто какой переход ставит — решает §2.
- <роль-специфичные: не коммитит / не стейджит / не правит код и т.п.>

## Intake (перед каждой итерацией)

По конституции §3: прочитать `AGENTS.md`, этот док и план целиком; записать
в `## Q&A log` intake-строку с digest'ами и явные `NO QUESTIONS` /
`NO SUGGESTIONS` / `NO OBJECTIONS` (или списки); <роль-специфичный пункт,
если есть>.

## Фаза (PHASE=work)

1. Intake.
2. <работа по своим секциям плана до полноты handoff'а>
3. Handoff: поставить `**Status:** <статус>` — переход и условие по §2;
   строка в `## Evidence`; краткий отчёт Manager'у.
4. Ждать CENSOR-проход или следующий диспатч.

## CENSOR-проход (PASS=censor) — для Architect / Planner / Coder

Сверка собственного handoff с файлами, не с памятью (§4): шапка плана,
свои секции, чужие зоны не тронуты. FAIL-находки правишь в своей зоне,
затем receipt по формату §4 — в `## Evidence`. FAIL по существу → откатить
handoff-статус, причина в `### <Role> objections`, правка, повтор фазы.

## Вердикт (вместо CENSOR) — для reviewer-ролей

Ревью по своему лейну; итог — вердикт `pass | needs-fix` в review-артефакте
`docs/reviews/<PlanID>_review.md`. Код не правишь; needs-fix — возражения
строкой в `### <Role> objections` плана. CENSOR у reviewer-ролей нет (§4).

## Стоп-лайны

Вопрос-блокер → строка `to=Owner, blocker:` в `## Q&A log` — и стоп.
<роль-специфичные стопы>. Повторы — по стоп-матрице §6.
```

## Анти-дрейф (для автора роли)

- Чек-листы и гейты живут в плане (`docs/plans/_template.md`), не в роли —
  роль ссылается на план, не копирует чек-листы.
- Дубликат правила из конституции допускается только с пометкой
  `DUPLICATE OF AGENTS.md §N — синхронизировать при правке`.
- Запрещено дублировать статусную модель: §2 `AGENTS.md` — единственный
  источник (статусы, «кто следующий», кто ставит переходы).
- Роль ≤ 250 строк; механика «как делать» длиннее памятки — не в роль
  (план, review-артефакт, playbook).
- Правка роль-дока = правка контракта: план фиксирует смену digest'ов
  (§3 п.7); конституционные решения — в Evidence плана.
