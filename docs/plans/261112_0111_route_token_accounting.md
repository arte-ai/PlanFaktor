## Solution / Decisions
<!-- owner: architect; решения уровня «что и почему», без детализации -->

1. **Носитель — секция `## Token usage (append-only)` в плане** (после
   `## Evidence`). Основная каноническая строка — формат фиксированный,
   grep/awk-дружелюбный, пасс обязателен:

   ```
   - YYYY-MM-DD HH:MM:SS — usage: <role>.<pass> <N> tokens — <source>
   ```

   `<role>` ∈ {architect, planner, coder, reviewer-risk,
   reviewer-contracts}; `<pass>` ∈ {work, censor, r1, r2, …} (work —
   основная фаза, censor — CENSOR-проход, rN — ВСЕ повторные диспатчи
   needs-fix-раунда N, не только ревью); `<source>` ∈ {dispatch,
   sendmessage, unknown}; `N` — целое ≥ 0 либо `unknown (why=<причина>)`.
2. **Пишет только Manager, сразу после получения результата вызова** —
   число из tool-результата харнесса, не из слов роли (notice ≠ mutation
   truth). Роли к секции не прикасаются. Харнесс не вернул usage — строка
   с `unknown (why=...)`; пропуск строки запрещён.
3. **Честность источника**: в комментарии секции (и в шаблоне) —
   дисклеймер: числа — учёт харнесса ZCode (`subagent_tokens`),
   приближение к расходу, не биллинг провайдера.
4. **Manager-контекст — вторая каноническая форма, best-effort**: на
   Owner-гейтях и в финальном отчёте Manager записывает строку

   ```
   - YYYY-MM-DD HH:MM:SS — usage: manager-context checkpoint ~<N> tokens-left — approximate
   ```

   если харнесс показывает остаток бюджета сессии. Чекпоинт-строки
   агрегатором считаются отдельно и в dispatch-суммы не входят; отсутствие
   чекпоинта — не нарушение.
5. **Агрегация — расширение `/planfaktor-status`** (POSIX grep+awk без
   mktime-зависимости, в духе `check_corpus.sh`; реверс оговорки «без
   скриптов» из плана 261111_0320 / шага 5 команды — фиксируется записью
   в decisions.md):
   - по активному плану: таблица `роль.пасс | диспатчей | токены` + итог;
     unknown-строки в сумму не входят (итог — нижняя граница:
     `>= N (+unknown: k)`); чекпоинты — отдельной строкой;
   - по Done-планам: `план | wall-clock | токены-итог` — закрывает S1
     (длительности + токены в одной таблице; якоря длительностей — правила
     из плана 261111_0320);
   - планов без usage-строк — graceful `нет данных (pre-261112_0111)`,
     не ошибка.
6. **Линт — `scripts/check_corpus.sh`**:
   - новая проверка **C11**: формат usage-строк обеих канонических форм
     (dispatch-форма п.1 и чекпоинт-форма п.4), роль/пасс из множеств,
     `N` — целое или `unknown (why=...)`; cutoff ≥ `261112_0111`
     (раньше секции не существовало); selftest-дефекты для обеих форм;
   - **перевод C3/C8 на cutoff-версионность**: C3 = «секции плана ⊇
     замороженный список обязательных секций (13 на момент 261111_2243)»,
     а не равенство живому шаблону; секции, добавленные в шаблон позже,
     обязательны только для планов с Plan ID ≥ плана, вводящего секцию;
     C8 аналогично. Проверено Architect'ом на intake 2026-11-12: C3 в
     дереве — «живой шаблон» (секции берутся из `_template.md` на каждом
     прогоне), план 261111_2243 уже Done и скрипт в дереве — правка
     реальна, не no-op; зависимость «после merge 2243» из Tests/DoD
     снята.
   - Implementer-заметки (из тех-валидации): детектор с якорем
     `^- <TS> — usage: ` (без якоря ловит примеры формата в прозе);
     не фильтровать вывод через `grep -n` (префикс `NN:` ломает якорь);
     `grep -c` возвращает exit 1 на нуле — не под `set -e`.
7. **Конституционные правки — безусловные** (не «по решению Architect»):
   - `AGENTS.md` §1 write-surface — новый пункт (f): usage-строки в
     `## Token usage` по формату шаблона — зона Manager'а;
   - `AGENTS.md` §5 — список append-only логов дополняется
     `## Token usage`.
   Обе правки — контракты → миграционные записи §3 п.7 + запись в
   `docs/decisions.md`.
8. Ретроспектива невозможна и не делается: планы до 261112_0111 без
   usage-данных остаются таковыми (истины нет — не выдумываем).
