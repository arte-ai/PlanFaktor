## Как я понял задачу
<!-- owner: architect; 3–7 строк; обязательна при Architect intake -->

Безусловный Owner-гейт «стартуем» (`Ready for Coder` → `In progress`)
упраздняем по решению Owner: четыре резиновых штампа подряд на планах
261111_1455–261112_2236 — трение без ценности, когда открытых вопросов
к Owner нет. Вместо него — модель предков: Owner дёргается только по
материализованным открытым вопросам в `## Q&A log` (Q с `to=Owner` /
`needs_owner: yes` без закрывающей A-строки), а точкой чтения человеком
становится блок «Как я понял задачу» + границы Scope — Manager
ретранслирует их Owner'у при моём выходе (`Draft → Ready for Planner`),
информационно, без подтверждения. Переход в `In progress` ставит Manager
автоматически при чистом Q&A (перечитывание секции, якорный
`grep -E '^- Q\('`), открытые вопросы — стоп по §6; единственный
обязательный гейт — merge. Носители старого гейта (11 файлов) зачищаются
целиком; исторические планы — append-only, не трогаем.

## Problem
<!-- owner: architect; пронумерованные пункты -->

1. Безусловный гейт «стартуем» (`Ready for Coder` → `In progress`) на
   планах 261111_1455–261112_2236 — четыре резиновых штампа подряд (Owner
   признал: «я даже не читал»): трение без ценности, когда к Owner нет
   открытых вопросов.
2. Родительская модель (приватные первоисточники; ссылки исключены из публичного репо): Owner дёргается только по материализованным
   открытым Q&A; понимание — обязательный
   человекочитаемый блок `## Как я понял задачу` 3–7 строк; перевод без
   избыточного подтверждения, если нет новых вопросов/изменений
   scope/развилок.
3. Текущая конституция жёстко требует оба гейта — противоречит решению
   Owner и родительской модели.

## Solution / Decisions
<!-- owner: architect; решения уровня «что и почему», без детализации -->

1. **Гейт «стартуем» упраздняется** (§2): переход `Ready for Coder →
   In progress` ставит Manager автоматически, если к Owner нет открытых
   вопросов. **Открытый вопрос** (для этой точки): в `## Q&A log` плана
   есть строка-вопрос `Q(<роль>): ...` с `to=Owner` или
   `needs_owner: yes`, ниже которой нет закрывающей строки
   `A(<кто>): ... status=closed`. Механика — **перечитывание секции
   Manager'ом** (рутина — модель, не скрипт): вспомогательный якорный
   grep `grep -E '^- Q\(' <план>` навигирует по строкам-вопросам;
   решение об открытости — по паре Q→A (Q-строки append-only вечны со
   своим `status=open` — закрытие живёт в A-строке, поэтому «голый» grep
   по `status=open` некорректен). Открытые вопросы есть → стоп по §6:
   `blocker` расширяется формулировкой «включая `needs_owner: yes` без
   закрытия»; закрытых нет → перевод.
2. **Точка чтения человека — выход Architect'а**: при переходе `Draft →
   Ready for Planner` Manager ретранслирует Owner'у блок
   `## Как я понял задачу` + границы Scope (в чат) — информационно, без
   подтверждения. Блок обязателен ролью Architect (docs/roles/architect.md);
   Manager цитирует, не пересказывает. Вопросы `to=<роль>` (не к Owner)
   авто-переход не блокируют.
3. **Merge-гейт — единственный обязательный** (§8, шапка шаблона): строка
   `**Owner gates:**` — «merge (`In review` → `Merged`); вопросы
   `to=Owner` — по мере возникновения».
4. **Полная зачистка носителей старого гейта** (все — в Scope/D8):
   `AGENTS.md` (§1 строка Owner, §2, §8), `docs/plans/_template.md`
   (шапка), `.zcode/commands/planfaktor-run.md` (routing + «Всегда»),
   `.zcode/commands/planfaktor-plan.md` (шаг ретрансляции),
   `.zcode/commands/planfaktor-status.md` (гейт-строка),
   `docs/lifecycle.md` (весь файл: карта цикла, фазы, «Гейты Owner»),
   `README.md` (quickstart), `docs/roles/index.md` (контракт!),
   `docs/plans/README.md` (таблица переходов), `CONTRIBUTING.md`,
   `docs/playbooks/manual_terminal_recovery.md`. Исторические планы
   (Evidence/шапки Done-планов) НЕ перезаписываются — append-only.
5. `/planfaktor-status.md`: «какой гейт Owner ждать» → «merge; открытые
   вопросы к Owner».
6. Все контракты (AGENTS, шаблон, роли/index, команды) → миграционные
   записи §3 п.7 + запись в decisions.md (решение Owner, выдержки первоисточника
   с корнем приватный первоисточник).
7. Новых линт-проверок нет: перечитывание Q&A — рутина Manager'а
   (qa-lint — backlog v2).
