## Problem
<!-- owner: architect; пронумерованные пункты -->
1. Расход токенов на план известен только постфактум: ни Manager на гейтах,
   ни Owner не видят отклонение от нормы до closeout; manager-context
   чекпоинты пишутся без сверки с какой-либо нормой.
2. Патологии расхода (прецедент: 261113_1642 — 47.3M, +130% к медиане
   из-за recovery-гонок и повторных диспатчей) всплывают только в ручном
   разборе — в момент, когда влиять уже поздно.
3. Норма нигде не зафиксирована: «много это сколько» каждый раз решается
   по наитию; статистическая база для тиров теперь есть и не используется.

## Solution / Decisions
<!-- owner: architect; решения уровня «что и почему», без детализации -->
1. **Носитель тиров — `docs/reference/budgets.md` (NEW)**: текущие тиры,
   статистика-обоснование и правило пересчёта. Числа НЕ в конституции —
   движущаяся статистика; конституция ссылается на носитель.
2. **Тиры** (предложение, утверждает Owner на merge-гейте): выводятся
   детерминированным правилом из квартилей per-plan-сумм — метод
   (n+1)·p с линейной интерполяцией, тир = квартиль, округлённый вниз
   до целых M:
   - `warn = 28M` (P75 = 28.4M) — информационная заметка в GATE-докладе;
   - `discuss = 42M` (P90 = 42.2M) — Manager обязан приложить в GATE-доклад
     обоснование: разбивка расхода по ролям/проходам/раундам из Token usage.
   НЕ жёсткий стоп: конвейер без рантайма, решение за Owner (§6 owner-silence
   и стоп-матрица не затрагиваются).
   rejected alternative: discuss=40M «круглое число» — why: не выводится
   правилом (фактический P90 = 42.2M), ломает детерминизм пересчёта на
   MINOR-релизах.
3. **Точка сверки — Owner-гейты и closeout**: Manager суммирует numeric
   usage-строки секции Token usage (awk-паттерн — в budgets.md) и сверяет
   с тирами; заметка — строкой в GATE-докладе (§8). Чекпоинт-строки
   manager-context в суммы не входят (конвенция 0111 сохраняется).
4. **/planfaktor-status**: рядом с суммой — маркер тира (ок / warn /
   discuss) по каждому измеренному плану; планы без usage — «нет данных
   (pre-261112_0111)» (существующий graceful-паттерн).
5. **AGENTS.md §8** — один буллет «Бюджетная заметка»: сверка на Owner-гейтах,
   носитель тиров budgets.md, warn — инфо, discuss — обоснование.
6. **Пересчёт тиров — при каждом MINOR-релизе** (естественный срез Done-планов).
   Правило в budgets.md: популяция — планы со статусом Done, PID ≥ 261112_0111,
   с ≥1 numeric usage-строкой (unknown и чекпоинты не входят); квартилы и
   округление — п.2; обновление чисел — в составе релизной операции Manager'а
   (без отдельного плана — числа, не контракты), шаг — в «Порядке» конвенции
   релиза (docs/releases/README.md). Первичное заполнение — этот план.
7. **Самоприменение**: merge-гейт этого плана несёт бюджетную заметку о
   собственном расходе (первый живой прогон механики).
