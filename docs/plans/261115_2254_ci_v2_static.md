## Problem
<!-- owner: architect; пронумерованные пункты -->

1. Единственный исполняемый артефакт репо (`scripts/check_corpus.sh`,
   ~2000 строк POSIX sh) верифицируется только собственным прогоном:
   синтаксические регрессии и shell-антипаттерны не ловятся статическим
   анализом ни локально, ни в CI.
2. Workflow-файл `.github/workflows/corpus.yml` не валидируется
   специализированным линтером GitHub Actions: ошибки выражений/синтаксиса
   проявляются только упавшим CI-прогоном (или молча).
3. Свежий план, инстанцированный из `docs/plans/_template.md`, впервые
   проверяется линтом только когда Manager создаёт реальный план:
   рассинхрон шаблона и линта (класс C3/C8 и шире) обнаруживается в живом
   плане, а не на этапе правки шаблона в CI.
4. Прогоны Owner 2026-11-13 были разовым аудитом: их исход (43/0, PASS,
   зелёный smoke) не закреплён регрессионной сетью — состояние «корпус
   статик-чист» не охраняется и может деградировать незаметно.

## Solution / Decisions
<!-- owner: architect; решения уровня «что и почему», без детализации -->

1. **Джоба `static` в существующем workflow corpus.yml** (не отдельный
   workflow-файл, не расширение существующей lint-матрицы): три шага —
   shellcheck, actionlint, smoke; триггеры/permissions/concurrency
   наследуются уровнем workflow. rejected alternative: отдельный
   workflow-файл — дублирует триггеры и identity concurrency без
   функциональной ценности. Имя workflow `corpus-lint` сохраняется:
   переименование — косметика, меняющая concurrency-identity на шуму
   в diff'е.
2. **Static-джоба без ОС-матрицы, `runs-on: ubuntu-latest`**: shellcheck и
   actionlint — платформо-нейтральные статические анализаторы, их прогон
   на двух ОС не даёт новой информации; BSD/GNU-чувствительная поверхность
   (POSIX grep/sed runtime) уже покрыта матрицей lint-джобы. Smoke-режим
   вызывает тот же линт на копии корпуса — идентичный вызову основной
   джобы, дополнительной ОС-чувствительности не вносит.
3. **Носитель профиля shellcheck — сам скрипт**: shebang-директива
   `# shellcheck shell=sh disable=SC2016,SC3012,SC2012,SC1007`; остаточные
   замечания гасятся построчными inline-директивами с обязательным
   кратким обоснованием (либо правкой кода, если прогон выявит реальный
   дефект — база Owner: 0). Целевое состояние: `shellcheck
   scripts/check_corpus.sh` без CLI-флагов — чистый exit 0. rejected
   alternative: disable-лист флагом `--exclude` в CI-шаге — профиль
   подавлений невидим локальному прогону разработчика и живёт вторым
   источником истины.
4. **Версии shellcheck/actionlint пиннятся явным тегом версии в
   workflow-файле; установка — прямые upstream-релизы (run-шаги), без
   third-party actions из маркетплейса.** Стабильность прогона от
   движущихся runner-образов (внезапные новые SC-замечания) важнее
   нулевой стоимости установки предустановленного shellcheck; trade-off
   supply-chain — прецедент 1944 (тег actions/checkout@v5 без SHA,
   минимальные права): пиннинг тегом версии инструмента не вводит новых
   экшенов; checksum-верификация бинарников и SHA-пиннинг — единый
   supply-chain follow-up (backlog, out of scope здесь). Конкретные
   номера версий — по актуальным стабильным релизам на момент кодинга.
5. **Smoke — режим `--smoke` самого `scripts/check_corpus.sh`** по модели
   `--selftest`: копия корпуса в mktemp-каталог (механика seed_corpus),
   инстанцирование плана из живого `docs/plans/_template.md`
   детерминированными подстановками (валидный уникальный Plan ID + имя
   файла по нему, статус из шаблона), полный прогон проверок C1–C14 по
   копии — итог `corpus: clean`; smoke-план живёт только в TMPDIR-копии,
   в репо не появляется. Инвариант «единственный исполняемый артефакт
   репо» сохраняется; CI-шаг = `scripts/check_corpus.sh --smoke`;
   локальная воспроизводимость из той же точки входа (канон README —
   локальный POSIX sh). rejected alternative: отдельный
   `scripts/*smoke*.sh` — второй исполняемый артефакт и дубль
   seed_corpus-механики; inline-блок в yml — логика теста невидима
   локально и вне канона верификации.
6. **Синхронные доки**: README (секция «supported verification
   environment»: состав CI = lint-матрица + static-джоба; флаг `--smoke`
   рядом с `--selftest`) и CONTRIBUTING (блок команд прогона: третья
   команда `--smoke`, актуализация «CI гоняет обе команды»).
