# Реестр внешних требований — Planfaktor

Единый носитель внешних требований (нормативных и клиентских): трасса
«требование → план → изменение → верификация → релиз» начинается здесь.
Регламент жизненного цикла — `docs/requirements/README.md`; производная
матрица трассируемости — `docs/requirements/matrix.md`; машинные
инварианты — линт C12 (`scripts/check_corpus.sh`). Реестр меняют роли
по планам конвейера; статусные переходы — только с записью в журнале
ниже (append-only).

## Формат row

Одна строка = одно требование, ровно 8 полей / 7 разделителей ` — `
(подсчёт полей — линт C12(б)):

`- <ID> — <формулировка> — предъявлено=<YYYY-MM-DD, кем> — принято=<none|<кем>, <YYYY-MM-DD>> — приоритет=<P1|P2|P3> — срок=<YYYY-MM-DD|none> — статус=<open|planned|verified|released> — plan=<PlanID|none>`

- `ID` — `REQ-<n>` (клиентское) или `G56939-<пункт>` (пункт
  ГОСТ Р 56939-2024); уникален, не переиспользуется.
- Формулировка не содержит ` — ` (длинное тире с пробелами): иначе
  счёт полей ломается; внутри формулировки — запятые, точки
  с запятой, скобки.
- `предъявлено=` — дата и предъявивший (5.3.3.2); `принято=` — принявший
  к реализации и дата, либо `none`.
- `приоритет=` — P1|P2|P3; `срок=` — предполагаемый срок реализации
  (5.3.3.2) либо `none`.
- `статус=` — `open|planned|verified|released`; `released` — требование
  выпущено (перевод при выпуске; конвенция релизного узла —
  `docs/releases/README.md`).
- `plan=` — PlanID плана, закрывающего требование; `none`, пока
  не промоутнуто (линт проверяет существование плана).
