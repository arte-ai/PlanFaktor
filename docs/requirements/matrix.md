# Матрица трассируемости — derived view

Производная поверхность над `docs/requirements/registry.md` и корпусом
планов: руками не ведётся, пересобирается при каждом изменении реестра
или статусов планов (дисциплина derived-поверхностей, CONTRIBUTING.md).
Автогенерация скриптом — кандидат v2 (Follow-ups плана 261112_2236);
v1 — правила пересборки + grep-рецепт ниже. Столбцы: ID → планы →
DoD(Dn) → Tests(Tn) → review → коммиты → статус.

## Правила пересборки

- Считать только тела секций (от заголовка `^## ` до следующего
  `^## `), не полнофайловый счёт: полнофайловый счёт ловит прозу
  и примеры формата в Solution/шапках и даёт ложные строки матрицы.
- R-метки извлекать из тел `## Scope` и
  `## Acceptance criteria / DoD` планов, строки с `<!--` исключать —
  тот же секционно-якорный детектор, что у C12(а)
  (`scripts/check_corpus.sh`).
- DoD-метка `Dn` считается покрытой, если `(Dn)` упомянута в теле
  `## Tests / Commands` плана (та же связка, что C12(в)).
- Review — артефакт `docs/reviews/<PlanID>_review.md` (итоговый
  вердикт последнего Round); коммиты — `git log --grep='<PlanID>'`
  по конвенции `type(PlanID)` (§8 конституции).
- Статус — из row реестра на момент пересборки; после merge строки
  «предстоит»/«до merge» заменяются фактическими значениями.

## Grep-рецепт (v1)

    # строки планов, несущие R-метку <ID> (тела Scope/DoD, без комментариев):
    awk '/^## (Scope|Acceptance criteria \/ DoD)/{f=1;next} /^## /{f=0} f && !/<!--/' docs/plans/[0-9]*.md | grep '\[R: <ID>\]'
    # покрытие метки D<n> плана <PlanID> тестами (тело Tests):
    awk '/^## Tests \/ Commands/{f=1;next} /^## /{f=0} f' docs/plans/<PlanID>_*.md | grep -c '(D<n>)'
    # коммиты плана <PlanID>:
    git log --oneline --grep='<PlanID>'
