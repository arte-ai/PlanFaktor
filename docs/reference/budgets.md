# Токен-бюджеты конвейера — носитель тиров

Единственный носитель тиров расхода токенов на план и правила их
пересчёта (решение — план 261117_0221, Solution п.1–п.7). Числа —
движущаяся статистика: конституция (§8, «Бюджетная заметка») ссылается
сюда и чисел не несёт. Тиры — не жёсткий стоп: конвейер без рантайма,
информация и Owner-решение (§6 AGENTS.md не затрагивается).

## Тиры

| Тир | Граница | Действие Manager на Owner-гейтах и closeout |
|---|---|---|
| ок | сумма < warn | заметки не требует |
| warn | warn ≤ сумма < discuss | информационная заметка в GATE-докладе |
| discuss | discuss ≤ сумма | заметка + обоснование: разбивка расхода по ролям/проходам/раундам из `## Token usage` |

Текущие значения (срез релиза v0.2.0, 2026-11-17): warn = 27M, discuss = 40M —
выведены правилом пересчёта из P75/P90 среза (ниже), округлением вниз
до целых M. Отклонённая альтернатива «круглое» discuss без вывода
правилом — ломает детерминизм пересчёта (фиксация — план 261117_0221,
Solution п.2).

## Суммирование расхода плана (awk-паттерн)

Сумма расхода плана для сверки с тирами — сумма numeric-значений
dispatch-строк `## Token usage` (строки `unknown (why=...)` и
manager-context-чекпоинты не входят):

```sh
grep -E '^- [0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2} — usage: (architect|planner|coder|reviewer-risk|reviewer-contracts)\.(work|censor|r[0-9]+) ([0-9]+|unknown \(why=[^)]*\)) tokens — (dispatch|sendmessage|unknown)$' "$PLAN" \
  | awk '{ if ($7 ~ /^[0-9]+$/) t += $7 } END { printf "%d\n", t+0 }'
```

Тир суммы — по границам таблицы «Тиры» выше; маркер тира у сумм
агрегирует `/planfaktor-status` (шаги 6–7 команды несут константы
границ — см. «Пересчёт»).

## Пересчёт тиров

- Когда: при каждом MINOR-релизе — естественный срез Done-планов.
  Шаг операции — в «Порядке» секции «Полномочия и процесс» конвенции
  релиза (docs/releases/README.md); обновление чисел — в составе
  релизной операции Manager'а, без отдельного плана (числа, не
  контракты).
- Популяция: планы со статусом Done, Plan ID ≥ 261112_0111 (cutoff
  учёта usage), с ≥ 1 numeric usage-строкой; планы без usage-данных и
  строки unknown/checkpoint не входят.
- Метод: квартили per-plan-сумм, (n+1)·p с линейной интерполяцией;
  тир = квартиль P75 (warn) / P90 (discuss), округлённый вниз до
  целых M. Вывод детерминирован: никаких «круглых» чисел вручную.
- При смене чисел: обновить значения и дату среза в этом файле
  и константы границ шагов 6–7 `.zcode/commands/planfaktor-status.md`
  (ссылки в обе стороны — рассинхрон чисел виден при следующей сверке).
