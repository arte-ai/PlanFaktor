# Комплаенс-маппинг ГОСТ Р 56939-2024 — Planfaktor

Предъявляемый клиенту документ: какими механизмами и артефактами
конвейер Planfaktor закрывает пункты ГОСТ Р 56939-2024 «Защита
информации. Разработка безопасного программного обеспечения. Общие
требования» (введён 2024-12-20; текст — docs.cntd.ru/document/1310017763).

Область применения маппинга: Planfaktor — plan-driven конвейер ролей
для разработки и верификации собственного корпуса (контракты, планы,
скрипты), а не инструментальный стек. Строки соответствия честно
разделены на «реализовано» (механизм + артефакт-носитель в корпусе),
«частично» (механизм есть, границы заявлены) и «вне скоупа конвейера»
(чужие инструментальные процессы — закрываются инструментами за
пределами Planfaktor). Вход трассы требований — реестр
`docs/requirements/registry.md`, регламент —
`docs/requirements/README.md`, производная матрица —
`docs/requirements/matrix.md`.

## Честные границы: вне скоупа конвейера

Инструментальные и средовые процессы стандарта закрываются внешними
инструментами разработчика, не конвейером Planfaktor (план 261112_2236,
Out of scope):

| Пункт | Процесс |
|---|---|
| 5.7 | Моделирование угроз и описание поверхности атаки |
| 5.10 | Статический анализ исходного кода |
| 5.11 | Динамический анализ кода программы |
| 5.12 | Безопасная система сборки ПО |
| 5.13 | Безопасность сборочной среды |
| 5.14 | Управление доступом и контроль целостности кода при разработке |
| 5.15 | Безопасность используемых секретов |
| 5.16 | Композиционный анализ (SCA) |
| 5.17 | Проверка цепочек поставок на внедрение ВПО |

Процессы 5.1 (планирование), 5.2 (обучение), 5.6 (архитектура), 5.8
(правила кодирования), 5.19, 5.21–5.25 (нефункциональное тестирование
и эксплуатационные процессы) в этом маппинге не заявляются: отдельные
совпадения механики (5.1 — план-дисциплина, 5.8 — корпусный линт)
не выдаются за соответствие; при запросе клиента маппинг расширяется
планом через реестр требований.
