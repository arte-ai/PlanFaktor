# Canon sweep — уплотнение после merge-волны

Применяется после серии merge одного контура: несколько планов подряд
дописали одну тему (секции конституции, `docs/plans/README.md`,
lifecycle, роль-доки), и канон по теме стал длинным и
повествовательным. Sweep приводит тему к «коротко + pointers»: один
вход, плотные формулировки, ссылки вместо пересказа.

## Что делает sweep

- Канон темы (секции конституции, plans/README, lifecycle, роль-доки)
  переписывается без истории обсуждений: история живёт в планах
  (append-only), не в каноне.
- Каждый Decision/Constraint — 1–5 буллетов + pointer на план/backlog/
  канон, где решение зафиксировано; pointer — не в snapshot: snapshot
  не source of truth и из канона не цитируется.
- Sweep новых правил не создаёт — только уплотнение и указатели;
  изменение правил = план (обязательный инвариант, см.
  `docs/playbooks/contract_edit_invariant_map.md`).
- Норма чтения темы — effective spec (`docs/plans/README.md`): тема =
  самый поздний план + канон; ранние планы открываются только по
  ссылкам при неясности; после sweep вход в тему — через канон,
  не через историю.

## Границы

- Перед sweep обязателен invariant map: hard invariant не уплотняется
  до pointer'а — его формулировка и есть несущая.
- Линт (`scripts/check_corpus.sh`) прогоняется до и после: полный
  прогон зелёный; sweep не меняет грамматику носителей (C1–C16 держат
  форму, sweep держит прозу).
- Review-артефакты, исторические планы и логи — append-only, sweep их
  не трогает.
