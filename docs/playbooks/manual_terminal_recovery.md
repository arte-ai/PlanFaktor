# Ручное терминальное восстановление

Owner-only плейбук: конвейер встал намертво — субагент потерян, статус
завис, план противоречив. Не заменяет обычный роутинг `/planfaktor-run`;
задаёт безопасный порядок ручного вмешательства (AGENTS.md §6–§8).

## 1. Признаки терминального состояния

- `loop` исчерпан: одинаковый FAIL/blocker ≥ 2 раз, эскалация Owner уже была, продолжать некуда.
- Fresh-диспатч по §7 не спасает: хендл потерян, перезапуск роли повторяет сбой.
- Статус завис: handoff-статус стоит, а валидного CENSOR-receipt нет и не получить.
- План противоречив сам себе: секции ролей спорят, intake-objections не разрешены.
- Дерево расходится с планом: staged-изменения есть, а `In review` не стоит (или наоборот).

Обычный route (диспатч → CENSOR → гейт Owner) пробуется первым; ручное
вмешательство — только когда он невозможен.

## 2. Безопасная диагностика — только чтение

Перед любым исправлением собери картину read-only:

```sh
grep -H '^\*\*Status:\*\*' docs/plans/[0-9]*.md
ls docs/reviews/
git status --short
git log --oneline -5
```

Потом прочитай план целиком: `## Evidence` (`grep -n '(Role CENSOR)' <план>`
— есть ли CENSOR-receipt), `## Q&A log` (открытые `to=Owner`, `blocker:`),
`### <Role> objections`, последняя intake-запись, строка `**Status:**`.
Итог — readback: план, статус, что сломано, какие файлы dirty. Ничего
на этом шаге не менять.

## 3. Ручные исправления

Правит Owner (сам или через Manager по явному поручению). Правка — строка
`**Status:**`; причина дописывается записью в `## Q&A log`, чтобы следующий
диспатч видел вмешательство в файлах. Кто ставит какое направление (§2):

| Переход | Кто ставит |
|---|---|
| `Draft` → `Ready for Planner` | Architect |
| `Ready for Planner` → `Planning` | Planner |
| `Planning` → `Ready for Coder` | Planner |
| `Ready for Coder` → `In progress` | Manager (авто: открытых вопросов к Owner нет) |
| `In progress` → `In review` | Coder |
| `In review` → `Merged` | Manager (гейт merge + коммит) |
| `Merged` → `Done` | Manager (closeout) |
| `*` → `Superseded` | Architect/Owner |

- Откат статуса — на предыдущий переход таблицы, без перескока фаз; откат
  через CENSOR-гейт = повтор фазы той же ролью с новым intake.
- План не спасти → `Superseded` + строка-ссылка на преемника; план не
  удаляется и не переписывается.
- Ручной коммит — только Manager, только после явного Owner-«да», формат
  §8: `type(PlanID): summary`, type ∈ `feat|fix|docs|chore`.

## 4. Чего не делать

- Не править append-only логи (`## Evidence`, `## Q&A log`,
  `## Suggestions log`, `## Objections log`) — только дописывать.
- Не коммитить без решения Owner и вне формата §8.
- Не перезапускать диспетч вслепую: resend потерянному хендлу и повтор
  конверта без перечитанного статуса запрещены (§7).
- Не двигать статус через CENSOR-гейт без валидного receipt; не заполнять
  чужие секции плана; не править `docs/reviews/` задним числом.

## 5. Восстановление после вмешательства

1. `/planfaktor-run`: Manager перечитывает статусы и делает fresh-диспатч
   роли (конверт путей; план перечитывается целиком).
2. Fresh-диспатч не наследует прошлых обещаний роли: consumed
   authorization не наследуется, истина — файлы.
3. Сверь PRE_STATUS_LINE конверта со статусом из файла (с учётом отката §3).
4. Снова loop/owner-silence — стоп-матрица §6: стоп, доклад, Owner решает.
