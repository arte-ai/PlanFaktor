description: Обзор конвейера Planfaktor — статусы планов и следующий шаг
---

Routine основной сессии (Manager). Только чтение: никаких изменений файлов.

1. Собери истину из файлов:

   ```sh
   grep -H '^\*\*Status:\*\*' docs/plans/[0-9]*.md
   ls docs/reviews/
   ```

2. Для каждого плана проверь `grep -n 'to=Owner' docs/plans/<файл>` и
   валидность CENSOR-receipt: `grep -n '(Role CENSOR)' docs/plans/<файл>`.

3. Выведи таблицу `План | Статус | Чья фаза | CENSOR-receipt | to=Owner`:
   «Чья фаза» — переход по таблице §2 AGENTS.md и кто ставит следующий;
   «CENSOR-receipt» — маркер, вердикт, dispatch id, непустые Observations;
   «to=Owner» — открытые вопросы, особенно `to=Owner, blocker:`.

4. Назови следующий шаг по routing-таблице `/planfaktor-run`: какой диспатч
   роли или какой гейт Owner ждать (старт / merge / ответ на Q&A).

5. Для активного плана выведи таблицу `Фаза | Начало | Конец | Длительность`
   из меток `YYYY-MM-DD HH:MM:SS` (локальное время); метки выбирай
   детерминированно:
   - фаза роли (Architect/Planner/Coder): начало = intake-строка её
     рабочей итерации (первая intake фазы; intake CENSOR-итерации,
     записанная после строки завершения фазы, началом не считается;
     при needs-fix-повторах фазы бери последнюю рабочую итерацию);
     конец = строка завершения фазы этой роли в `## Evidence` —
     Evidence-узлы Manager'а (валидация CENSOR, гейты) конец фазы роли
     не закрывают;
   - фазы без ведущей роли: review (`In review`) — начало = строка
     завершения фазы Coder'а, конец = merge-узел Manager'а (запись
     о merge-коммите и переходе `Merged`); `Merged` — начало = узел
     перехода `Merged`, конец = closeout-узел `Done`;
   - длительность = конец − начало; текущая незавершённая фаза — elapsed
     от её начала (правила выше); отсутствующие метки (записи до
     введения формата) — прочерк.
   Чтение меток из Evidence и Q&A log, без скриптов.

6. Никаких изменений файлов — только чтение и доклад Owner.
